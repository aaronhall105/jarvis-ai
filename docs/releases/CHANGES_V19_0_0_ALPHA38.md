# Jarvis 19.0.0-alpha38

Alpha38 refines the shared alpha37 HomeExperience into a canonical,
physical-item-oriented presentation without creating another home-state model.

## Canonical home presentation

- Registry device IDs and shared hardware connections group physical camera,
  light, and media control surfaces deterministically.
- One camera card retains Clear, Fluent, snapshot, and analytical sources under
  Diagnostics while selecting one grounded primary stream.
- Technical unnamed light surfaces and secondary unavailable media paths no
  longer inflate normal Home cards or attention counts.
- Aggregate/container areas are excluded from Rooms through explicit or
  conservative structural classification.

## Cleaner Home and room experience

- Attention is based on meaningful canonical incidents and important primary
  device availability rather than every unavailable integration entity.
- Occupancy is concise and preserves the rule that absent camera detection does
  not prove an empty room; complete evidence remains available diagnostically.
- Energy presents grounded current demand, consumption, cost, and tariff values
  with human-readable unit and currency formatting.
- Android adds compact offline presentation, explicit Back affordances, rounded
  Diagnostics controls, contextual activity, and verified light actions beside
  the relevant Lights section.

## Compatibility and authority

- Core application version remains `3.7.0`.
- Realtime protocol remains `2`.
- Phone and Wear share versionCode `190400`, following the established +10
  alpha sequence from alpha37 (`190390`).
- Raw Home Assistant evidence is retained under Diagnostics, and all state
  changes continue through Core's frozen verified-action path.
